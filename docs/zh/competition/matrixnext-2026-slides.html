Sortie Deck

面向中大型产研团队的 AI 原生办公迭代控制面。可确认航线、产物契约与人在环，把传话成本换成可审计的出击。

队伍 SortieDeck 开源 Apache-2.0 编排 LangGraph 仓库 lpliu-art/sortie-deck-todos
01 · 问题

我们已经有 AI，为什么协作还是乱的？

中大型产研已经人手一个 AI，总线仍是人和 IM：各自开窗口、粘贴接力、截图当契约。接力越长，迭代越慢，决策越难回放。

产品→AI→需求文档→ 澄清会议→IM 传话→ 开发/测试各自的 AI→提测？
02 · 方案

把「聊天接力」换成控制面

Sortie Deck 不是又一个聊天框。按任务集结角色 Agent，用 LangGraph 编排出击航线， 关键门禁保留人在环，阶段之间用产物契约传递结果。

Brief→航线规划官→真人确认→ 角色 Agent→HITL→提测 / 交付

04 · 商业价值

少接力、快闭环、可审计、数据自持

面向中大型产品与工程团队的定性结果，不是客户案例，也不是实测数字。

降低接力成本

产品、工程、测试、发布沿同一条出击交接，不再把需求誊进各自的聊天窗口。

加快迭代闭环

航线确认后按阶段推进。并行波次对齐命名产物，不再干等群里对齐口径。

合规可回放

谁确认了航线、哪一关放行或打回、产物写在哪条路径，都留在控制面上。

开源，可本地部署

Apache-2.0。控制面、产物与知识可留在自有环境，出击上下文由团队自己掌管。

05 · 上下文平权

出击上的每个角色，读同一份真相

产品、工程、测试、发布共享同一份 Brief、已确认航线、命名产物和 HITL 决策。没有只活在某一次私人对话里的特权粘贴。

产品 同一 Brief 工程 同一航线 测试 同一产物 发布 同一 HITL

角色之间拉平

下游读命名文件。上下文属于这次出击，不属于最后粘贴的那个人。

知识与记忆按作用域到达

工作区、任务、角色作用域把该知道的上下文注入执行中的 Agent。阶段标签挡住并行分支串味，避免结论只留在某一个聊天记录里。

06 · 沟通协作

频道看得见，门禁说了算

小队频道是可见协作层。真相在航线、产物和 HITL。点名与斜杠命令是结构化操作，群里随手 @ 不再充当审批。

@product·@eng·@qa·@deploy → /confirm·/start·/approve·/rewrite·/stop

协作发生在明处

讨论、阶段消息和决策留在任务频道里，全员可见。IM 可以做通知，不能当真相源。

HITL 是一等门禁

interrupt() 暂停图。放行、打回、改写、停止、重路由回到同一条可恢复轨迹，并可以审计。

07 · 创新点

为什么不是「又一个 Agent 聊天」

控制面一等公民

任务、航线、HITL、产物都是一等对象，而不是埋在对话历史里。

可确认航线

规划官提案节点（含并行）；真人确认/手改后才编译图出击。

契约化产物

阶段写命名文件；下游读文件。并行路径作用域，避免互相覆盖。

图语义 HITL

interrupt() 暂停；放行 / 打回 / 改写 / 停止 / 重路由。
