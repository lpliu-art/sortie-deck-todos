# 目标与非目标

## 问题

办公软件迭代里，产品 / 设计 / 多端研发 / 测试 / 发布之间大量依赖「传话」：PRD 在聊天里、接口口头对齐、联调靠碰运气。Sortie Deck 要把这条链路收成 **可确认的任务控制面**：角色 Agent 执行阶段，产物按契约交接，关键门禁保留真人。

## 目标

- **以任务为中心**：一次出击 = 一条可起停的流水线 + 小队频道 + 产物目录。
- **契约化协作**：阶段输出命名文件；下游读文件，不读聊天粘贴。
- **可确认航线**：规划官提案 → 人手确认/手改 → 再编译 LangGraph。
- **可插拔执行**：mock / Claude Code / Cursor CLI / 部署壳等注册进同一编排。
- **人在环默认开启**：HITL、权限档、频道确认，而不是全自动黑盒。

## 非目标（当前）

- 不做通用「任意 Agent 聊天平台」或替身 IM。
- 不做完整 K8s / CRD 工作流引擎分叉。
- 不在本仓重做企业级向量检索引擎（知识检索可接 WeKnora）。
- 不以自研引擎替换 LangGraph（见路线图非目标）。
- 默认存储以本地友好的 JSON / SQLite 为主；多租户云库是后续选项。

## 成功判据

| 指标 | 说明 |
|------|------|
| 冷启动可演示 | mock 执行器下完整 HITL 出击可跑通 |
| 航线可改 | 确认前可增删改节点与并行组 |
| 产物可追 | 每阶段目录可读、契约可校验 |
| 文档可建站 | `mkdocs build` 通过 |
